The Model-Proof Kit

One paste builds you a portable AI brain: a small folder of files that tells any AI model who you are, what you're working on, and how to help you. When the next price war hits — and it will — you switch models in five minutes instead of starting from zero.

Why this exists: the week Kimi K3 dropped, model prices and subscription rules changed overnight. People whose entire setup lived inside one chat app were stuck. People whose contextContext = everything the AI knows about you: your goals, your projects, your preferences, your history. What you'll have in 20 minutes

  • A "Brain" folder on your computer with three small files any AI can read.
  • user.md — who you are: goals, work, family situation, how you like answers. .mdA .md (Markdown) file is just a plain text file. Every AI model on earth can read it. No app lock-in, ever. means plain text, readable by every model ever made.
  • memory.md — what's going on right now: current projects, open decisions, recent changes.
  • README.md — a one-page instruction sheet that tells any new AI how to use the other two files.

Step 1 — Create the folder

1

Make one folder, anywhere you can find it again

On Mac: open Finder → Documents → New Folder → name it Brain. On Windows: same thing in File Explorer. That's it. No app to install, no account to create.

If you use the Claude desktop app, connect this folder when asked — then Claude can write the files for you in Step 2. If you use any other AI (ChatGPT, Gemini, Kimi), you'll copy-paste the files it writes into the folder yourself. Both routes work.

Step 2 — The one paste

Open your AI of choice and paste this entire block. It interviews you first, then builds all three files. It pauses once, to let you confirm the interview answers, then finishes on its own.

I want to build a portable "AI brain" folder that makes my context work with ANY AI model, so I'm never locked into one company. Work through these four phases in order. Pause ONLY once: after Phase 1, show me what you captured and wait for my OK before writing anything.

PHASE 1 — INTERVIEW ME
Ask me, one question at a time (wait for each answer):
1. My name, age, where I live, and what I do for work.
2. My family situation, in one or two sentences.
3. The 3 goals that matter most to me over the next 12 months.
4. The projects or responsibilities I touch every single week.
5. How I like answers: short or detailed? Bullet points or prose? Any pet peeves?
6. The tools and apps I actually use daily.
7. One thing about me a new assistant always gets wrong at first.
Then summarize everything back to me in a short list and ask: "Correct and complete?" Wait for my OK.

PHASE 2 — WRITE user.md
Write a file called user.md containing: Identity (who I am), Goals (the 12-month three), How I Work (answer-style rules from question 5, stated as instructions to an assistant), Daily Stack (tools), and Watch-outs (question 7). Keep it under 60 lines. Plain language. This file changes rarely.

PHASE 3 — WRITE memory.md
Write a file called memory.md containing: Current Projects (from question 4, one line each with status), Open Decisions (anything I mentioned I'm weighing), and a Last Updated date at the top. Keep it under 40 lines. This file changes weekly.

PHASE 4 — WRITE README.md
Write a file called README.md addressed to "any AI model reading this folder." It must say: read user.md first to learn who I am and how to answer me, read memory.md second to learn what's current, trust user.md over your own assumptions, and ask me before acting on anything in memory.md older than 30 days.

If you can save files directly, save all three into my Brain folder. If you cannot, output each file in its own clearly labeled code block so I can copy each one into a text file myself. Then confirm what was built and stop. Do not add extra files. Do not add commentary inside the files.

If you're doing the copy-paste route: for each code block the AI gives you, open TextEdit (Mac) or Notepad (Windows), paste, and save into your Brain folder with the exact file name — user.md, memory.md, README.md. Choose "plain text" if asked.

Step 3 — The portability test

2

Prove it works with a model you've never used

Open a different AI than the one that built your files — any free one is fine. Paste the contents of all three files, then ask: "Based on my files: what should I focus on this week, and why?"

If the answer sounds like it comes from someone who knows you — the test passes. You just switched models without losing yourself. That's the whole trick, and now it's yours.

Step 4 — Keep it alive (2 minutes a week)

Once a week, paste this into whichever AI you're currently using, along with your current memory.md:

Here is my memory.md. Interview me for a maximum of 3 quick questions about what changed this week (projects moved, decisions made, anything new I'm weighing). Then output the updated memory.md in one code block with today's date in Last Updated. Change nothing in the file I don't confirm. Keep it under 40 lines.

Where this goes next: this three-file kit is the seed of a full second brain — the same architecture I run my whole life on: files first, app second, model swappable. Grow it by adding one folder per area of your life when a file gets crowded. The rule that keeps it portable: knowledge lives in files, never in any one app's chat history.
